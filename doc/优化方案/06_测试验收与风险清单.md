## 测试策略总则

| 原则 | 说明 |
|------|------|
| **夹具使用 mock 系统数据** | 所有测试使用预构造的 MetricsSnapshot / ProcessInfo 夹具，**不碰真实进程、不执行真实 kill、不删除真实文件** |
| **未测不声称通过** | 任何功能在测试编写并绿色前，不得在文档/README 中宣称"已实现" |
| **后端单元测试不依赖 Tauri runtime** | 纯 Rust 逻辑（safety/cleanup/monitor delta）可 `cargo test` 独立运行 |
| **前端测试 mock IPC** | `@tauri-apps/api/core` 的 `invoke` / `listen` 通过 vitest mock 替换 |
| **E2E 仅在 CI 手动触发** | 涉及真实系统状态的 E2E 标记 `#[ignore]`，需显式 `--ignored` 运行 |

### 本轮静态复查发现并修复（未纳入原任务表）

| 问题 | 修复 |

| 陌生偏好值可把界面打成空白页（2026-09-22 04:05 实测复现） | `z-biz-sys:v1:tab` 直接当作 antd `Tabs.activeKey` 用，写入产品里不存在的 key（旧版本改名残留、手改）时**一个面板都不渲染**：实测注入 `tab=netio` → `.ant-tabs-tab-active` 为 `null`、`aria-selected` 无匹配、内容区仅 67 字符（只剩 Header/停滞 Alert 文案）。改为以真实 `tabItems` 为唯一事实来源回落 `overview` 并把修正值写回；同时 `interval` 改为只接受 `INTERVAL_OPTIONS` 里的档位（此前 `Number(...) \|\| 1000` 会放进 `999999`，后端虽夹取，但界面用它乘停滞因子 → "采集停滞"永不触发），`trendRange` 沿用既有白名单。复测同一注入（`tab=netio` + `interval=999999` + `trendRange=12345`）→ 激活标签 `概览`、内容区 182 字符含 4 张指标卡与 `60 秒/5 分钟/1 小时` 三项、频率选择框显示 `1 秒`、落盘自愈为 `tab=overview / interval=1000 / trendRange=60`，console 仍 0 error / 0 antd 告警；`tsc` 0 error、`npm run build` ✓ 2.25s（1,534.53 kB / gzip 474.01 kB），`src/App.tsx` 609 行 |
