## 当前架构核心问题

每个 Tauri command 独立执行 `System::new()` → `refresh_xxx()` → 返回（[lib.rs L148-149](../../src-tauri/src/lib.rs)）。无共享状态、无缓存、无定时推送。sysinfo CPU 使用率需两次采样差值，首次 refresh 恒返回 0。前端从未调用这些命令，使用 `Math.random()` 代替。

## 推荐架构：单例采集器 + 事件推送

```
前端 useSystemMonitor() ← listen("sys://metrics")
前端 useProcessStore()  ← listen("sys://processes")
操作类命令仍用 invoke（kill/cleanup/scan）
        ↕ Tauri Event Bus
后端 MonitorService (tokio::spawn 定时循环)
  ├─ SystemState: Arc<Mutex<System>> 唯一实例
  ├─ 每 interval: refresh → compute_delta → emit("sys://metrics")
  └─ ProcessCollector: 独立 3s 间隔 → emit("sys://processes")
```

## R1 · 采集频率与 CPU 开销

| 指标 | 推荐值 | 依据 |
|------|--------|------|
| CPU/内存/网络刷新 | **1000ms**（可选 500/2000/5000） | sysinfo MINIMUM_CPU_UPDATE_INTERVAL=200ms；Activity Monitor 默认 1s |
| 磁盘空间刷新 | **10000ms** | 容量变化极慢 |
| 进程列表刷新 | **3000ms** | 枚举开销大（macOS ~50ms/次） |
| 自身 CPU 目标 | **< 2%**（空闲 < 0.5%） | 对标 Stats app ~1% |
| 自身内存目标 | **< 80MB** RSS | WebView ~50MB + Rust ~25MB |

## R2 · 异步采集与背压

- 采集循环：`tokio::time::interval` + `MissedTickBehavior::Skip`（前帧超时则跳过，不追赶）
- 事件推送：fire-and-forget，前端未 listen 时丢弃，无队列堆积
- 进程流：仅 Tab 激活时推送（`start_process_stream` / `stop_process_stream` 控制）
- 采集 panic：`catch_unwind` 包裹，日志记录后重启循环

## R3 · 数据缓存与增量刷新

| 数据类型 | 策略 | IPC 量 |
|----------|------|--------|
| 静态信息（hostname/OS/CPU型号） | 启动采集一次，常驻 | 一次性 ~200B |
| CPU/内存/网络 | 每帧全量（数据量小） | ~800B/帧 |
| 磁盘空间 | 10s 刷新，仅变化分区推送 | ~200B/帧 |
| 进程列表 | 3s 刷新，前端 PID-diff 更新 | ~40KB/帧（200进程） |
| 历史趋势 | 前端环形缓冲（60/300/3600点） | 本地，不走 IPC |

总 IPC 带宽 < 15KB/s，远低于 WebView 处理能力。

## R4 · 跨平台采集差异与抽象

```rust
// 规划新增: src-tauri/src/platform/mod.rs
pub trait PlatformCollector {
    fn memory_pressure(&self) -> MemoryPressure;
    fn network_interfaces(&self) -> Vec<NetIf>;  // IP/MAC/speed/status
    fn temperature(&self) -> Option<Vec<TempSensor>>;
}
```

| 能力 | sysinfo 0.30 覆盖 | 补充方案 |
|------|-------------------|----------|
| 接口 IP/MAC | ✗ 不提供 | `pnet` crate 或平台原生 API |
| 内存压力 | ✗ | macOS `task_info` / Linux `/proc/pressure` / Win `GlobalMemoryStatusEx` |
| 温度 | ✗ | macOS IOKit / Linux hwmon / Win WMI |
| 进程线程数 | ⚠ 仅 Linux | macOS `proc_pidinfo` / Win `NtQueryInformationProcess` |
| 磁盘 I/O | ✓ | sysinfo DiskUsage 已支持 |

**推荐**：升级 sysinfo 至 0.33+（API 变更需适配），引入 `pnet` 处理网络接口。

## R5 · 大进程列表虚拟化

**后端**：`get_processes` 增加 `offset/limit/sortBy/filter` 参数，默认 top 200（CPU 降序）。

**前端**：Ant Design Table `virtual` 属性或 `react-window`；行高 40px，可视 ~15 行，缓冲 5 行。

**IPC 契约（规划新增 `src/ipc_contract.ts`）**：

```typescript
interface ProcessQuery {

  filter?: string; showKernelThreads?: boolean;

```

## R6 · 内存占用控制

| 组件 | 目标 | 措施 |
|------|------|------|
| Rust 后端 | < 25MB | 单例 System ~8MB + 进程缓存 200×200B=40KB |
| WebView | < 55MB | 虚拟列表 + 环形缓冲（非无限增长） |
| 总 RSS | < 80MB | 历史持久化写磁盘不驻留内存 |

趋势数据内存：60s=1.9KB, 1h=115KB, 24h(10s采样)=276KB，全部 < 1MB。

## 核心数据模型

### MetricsSnapshot（每帧推送）

```typescript
interface MetricsSnapshot {
  timestamp: number;
  cpu: { total: number; perCore: number[]; frequency?: number };
  memory: { total: number; used: number; available: number; swapTotal: number; swapUsed: number; pressure: 'normal'|'warning'|'critical' };
  disks: Array<{ name: string; mountPoint: string; total: number; used: number; free: number; readBytesPerSec?: number; writeBytesPerSec?: number }>;
  networks: Array<{ interface: string; status: 'up'|'down'; ipv4?: string; mac?: string; rxBytesPerSec: number; txBytesPerSec: number }>;
  uptime: number;
}
```

### IPC 事件契约

| 事件名 | 方向 | 频率 | Payload |
|--------|------|------|---------|
| `sys://metrics` | 后端→前端 | 每 interval | MetricsSnapshot |
| `sys://processes` | 后端→前端 | 3s（Tab 激活时） | ProcessPage |
| `sys://alert` | 后端→前端 | 阈值触发 | AlertEvent |
