## F8 · Agent 辅助诊断（P2）—— ✅ 已随 T5-04/05/06 落地（2026-09-22）

- 自然语言查询："哪个进程占 CPU 最高？" → 采集 → 排序结果 —— ✅ 5 个示例问句直接挂在输入框下方（点一下即问），实测识别 9 类意图（进程排行 / 综合诊断 / 内存压力 / 磁盘空间 / 网络吞吐 / 启动项 / 垃圾清理 / 温度风扇 / 未识别）
- 异常诊断："为什么这么卡？" → 分析 CPU/内存/磁盘/进程 → 诊断报告 —— ✅ 结论行带等级标签（正常 / 偏高 / 越限）+ 指标名 + 数值，阈值**就是告警设置里那一份**（不另起一套口径）
- 操作建议：渲染为"待确认卡片"，用户点击才执行，**Agent 不自动执行** —— ⚠ **落地时比原方案更窄，且这是刻意的**：点击**不执行任何东西**，"确认"只等于**跳转**。全部可用动作只有两种 —— 打开某个页签、把某个 PID 填进进程表关键字并跳过去。原句里"用户点击才执行"的写法会让人以为存在一条"点了就 kill"的通路，实际不存在也不打算存在：终止进程、清理文件、刷新 DNS 都必须在对应页面由用户确认后走各自的校验流程（`validate_kill` / 路径白名单 / `PERMISSION_DENIED` 文案）。面板右上恒挂 `只建议 · 不执行`，回答卡片右上恒挂 `已执行：否`（常量，不是状态位）。
- 安全边界：禁止直接调用 kill/cleanup/disable（见 [04 文档 S4](./04_数据安全与可靠性.md)）—— ✅ 已可证：`Suggestion` 枚举只有两种导航模板、`Reply.executed` 私有恒 false、Reply 的 JSON 递归 key 审计禁止 command/args/path 类字段、三条源码文本审计分别扫引擎生产切片 / `commands.rs` 的 Agent 分节 / **前端** `AgentPanel.tsx`（由 cargo 单测从 `CARGO_MANIFEST_DIR` 读进来），另加"像要求代为执行的自由文本一律 `refused` 且不生成命令文本"

**交互实测口径（2026-09-22）**：诊断助手是**顶层页签**（`agent`），不塞进"系统信息"底部 —— 它是一次问答而非一组配置，且入口要在。空态不假装忙：没有回答时显示"这一轮没有任何结论。"，无来源数值一律画 `—`（后端给 `null`，绝不填 0）。提问中禁用输入并显示"正在读取采集快照…"，答案到达即替换。**一问一答、不留会话**：界面上没有历史列表，因为多轮上下文需要服务端状态，而 04 的持久化最小化口径不允许为一个诊断助手开新落盘。

> **I-17 的交互口径（2026-09-22 实测）**：入口是顶栏"迷你模式"按钮 + 全局 `m` 键，退出是 `Esc` 或迷你条上的"退出迷你"按钮。三条是刻意定的：**① 不缩原生窗口**（方案原句"缩小窗口"要靠 `set_size` 或原生托盘，而 capabilities 里只有只读窗口 getter ⇒ 那是与 T5-02 同一道授权门槛，先问再动），**② 不进偏好快照**（`miniMode` 是会话级 state：退出应用不记住上次是不是迷你，同 T5-10 把视图态挡在 `PrefsSnapshot` 之外），**③ 不在前端判越限**（读数颜色按后端回过的 warning 档上色，"越限"文案只来自 `sys://alert`；所以迷你条上写的是"越限线 80 %"而不是一条自己算出来的告警）。键位让位规则：带 `meta`/`ctrl`/`alt` 的组合键不动、任何浮层（告警抽屉/偏好对话框/清理确认/详情/kill 确认）开着时不动、焦点在 `input`/`textarea`/`contenteditable` 里时不动 —— 否则在进程搜索框打 `m` 会把界面切走。一屏的内容：采集状态徽标 + CPU（含核数）/内存（含后端压力档）/磁盘（含挂载点与剩余）/网络（两接口之和）/运行时长五项读数、频率选择框、CPU 与内存两根迷你折线（各自标窗口与点数）、一行告警状态，下面才展开每核心/磁盘/网络三块明细。**进入迷你模式会停掉进程枚举流**（实测 `stop_process_stream` 2 次：effect cleanup 与 `if (!active)` 分支各一次，后端只是设 bool 故幂等），因为那一屏没有进程表却要每 3 s 枚举全机器进程是没道理的。**无首帧时五项全 `—`** 且折线写"采样点不足"、明细面板给出显式空态，不出现任何 0 值占位。900×600 与 560×420 两档实测：无横向/纵向滚动、迷你层不被裁切、退出按钮四边在视口内。测量与断言清单见 [06](./06_测试验收与风险清单.md)。**未验**：真实 Tauri 窗口/WKWebView 里的渲染与字体度量、中文输入法候选态下的 `m` 键。

> **I-16 的交互口径（2026-09-22 实测）**：页容量选择器放在进程卡片右上角"搜索框 + 刷新"这一组里（`Select` 小尺寸，文案 `N 行/页`），不新开工具条。改动页容量**一律回到第 1 页**，因为从第 6 页×20 行切到×200 行时旧偏移会落到新结果集的空段；选项表只有 `[20, 50, 100, 200, 300]` 五个值、白名单外的输入被直接忽略，最大那个刻意等于后端上限而不是超过它。页脚如实交代渲染方式："可视窗口渲染（共 N 行数据）"（N 是当前这一页真实拿到的行数，不是被裁后的窗口行数）或"整页渲染"，并保留原有的"命中总数 / 第 X / Y 页 / 起止序号"。虚拟滚动本身对用户不可见，可见的只有：切到 300 行/页时表格变成一块 560 px 高、内部滚动的区域（实测 500 行时 `scrollHeight` 19 532 px）。翻页时滚动位置是否回到顶部**没有验过**，`ProcessTab` 也没为它写代码 —— 留给下次真机点验。
>
> **I-15 的交互口径（2026-09-22 实测）**：入口在"系统信息"Tab 底部（不在顶栏，避免与"刷新/暂停"抢位）。导出走原生保存框，界面只显示**文件名**不显示整条路径；导入是**两步**：先"预览"逐行给出 `采纳 / 夹取 / 缺失 / 不合法` 四种结局，并原样列出文件里那一栏的原始值（"你说的 1500 我折成了 1 秒"必须看得见），确认后才整份替换；文件里有但本版本不认的键**只报告不写入**；一项都没变时如实提示"与当前一致"，而不是假装成功。取消原生对话框算无操作，不弹错误提示。落盘实现与安全边界见 [04 SEC-V11](./04_数据安全与可靠性.md)，实测证据见 [06](./06_测试验收与风险清单.md)。
