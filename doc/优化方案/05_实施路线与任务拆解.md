**已知限制（真实采集边界）**：

- 进程线程数：sysinfo 0.33 仍只在 Linux 提供 → 进程表已移除该列，不再显示假值
- macOS 可用内存：`free+inactive+purgeable-compressor` 口径在压缩内存高时会 saturating 归零 → `memory_metrics()` 取 `total - used` 作为下限（该段实现 0.30.13 → 0.33.1 逐字未变，见下文对账）
- 磁盘读写速率：是**块设备**计数而非卷计数，同一物理盘上的多个 APFS 卷（`/` 与 `/System/Volumes/Data`）显示同一份数值；且为采样窗口（默认 10 s）均值，窗口内每帧重复同一个数
- Windows 网卡 IPv4/IPv6/MAC：未实现 `GetAdaptersAddresses` → 返回 `None`
- 启动项操作只覆盖**文件型**来源：macOS `~/Library/LaunchAgents/*.plist`、Linux `~/.config/autostart/*.desktop`。Login Items（要 System Events 自动化授权）、Windows 注册表 Run 键、systemd 用户单元（要 `systemctl`）三类**只枚举不操作**，由后端 `operable=false` 打标、界面显示"不支持在此操作"标签而不是按钮
- "禁用"不写 plist 的 `Disabled` 键、不碰 `launchctl`：它就是把文件移出启动目录，所以 `enabled` 一字面意思是"文件此刻在不在启动目录里"，界面与 message 都按这个说法写
- "删除"也不物理删除：文件移到 `startup-backup/<来源>/out/`，之后不再列出，需要用户自行清盘
