## 2. 调查记录

### 2.1 T3-02 的根因：后端落盘历史里**没有按接口拆分**的字段

- `src-tauri/src/history.rs:41-48` `HistoryPoint { t, cpu, memory, rx_bytes_per_sec, tx_bytes_per_sec }`
  —— 上下行速率是**全机聚合**的，**没有 per-interface 维度**。
- `src-tauri/src/monitor.rs:81-87` `NetworkMetrics` 才有 `interface` / `rx_bytes_per_sec` /
  `tx_bytes_per_sec`，但它只随**实时帧**推送，不落盘。
- ⇒ 「是哪个网卡在跑流量」这个问题，**靠现有落盘历史答不了**。
  `lib/trend.ts` 那套 `windowHistory` + `resampleEnvelope` 走的是落盘历史，
  拿来做 per-interface 曲线只会得到一条又一条聚合线。

⇒ 所以本轮的方案是：**前端按接口各自维护一条滚动时序**。
这不是「退而求其次」：后端要把 per-interface 历史落盘，得改 `HistoryPoint` 的
结构与**已落盘文件的格式**（`points.jsonl`）—— 那是一次破坏性迁移，
而 T3-02 这一条的验收标准是「per-interface **实时曲线**」，没说必须落盘。
（若日后要做「跨重启的 per-interface 曲线」，那是一次独立的后端改造，
不在本条范围内。）

### 2.2 T4-09 的根因：本仓**根本没有 i18n 机制**

台账 00 里的核对记录写得很准：`grep -rn "i18n\|locale"` 在 `src/` 下 **0 处命中**。
一个只有中文的界面，「把 title 本地化」没有落脚点 ——
台账给的处置是「要么补 i18n 基建，要么把任务表标准改成『title 用词本地化』」。

本轮选**补基建**，理由：只改任务表标准等于把验收标准降级（那正是本仓
反复记在案的「过宽的抬头 vs 过严的任务表」分歧的另一面）。

## 3. 改动清单

### 3.1 T3-02

**新增 `src/lib/networkSeries.ts`**（纯逻辑，无 React / 无 IPC，可 `node --test` 直接跑）：
- `appendNetworkFrame(prev, snapshot, maxPoints)` —— 把一帧采集并进**每个接口各自**的队列。
  - **返回新的 Map，不改动入参**（只复制这一帧要写的队列）。
  - **同一时刻的重复帧 → 替换而不是追加**（否则图上出现零宽度的重复点，
    读数与图对不上）。
  - **空帧 / `networks` 缺失 → 什么都不做**（数据流停了就停在那儿，
    **不补合成点**；后端停采时前端拿到的是同一个对象引用，effect 不会重跑）。
  - **这一帧没出现的接口：历史保留但不再增长**（网卡一抖一抖时曲线不该一段段消失）。
  - **点数有界**（每接口 600 点）、**接口数有界**（32 个；
    veth 这类一次性网卡名不能把内存撑爆；超限时丢**最久没更新**的，不是最旧创建的）。
- `networkPoints` / `networkRows`（time 用 `formatClock`，与 `TrendChart` 的 XAxis 对得上）
  / `summarizeNetwork`（峰值 / 均值 / 末值；**空序列不返回 NaN** ——
  NaN 会让界面显示 "NaN"，比显示 0 更糟）。

**新增 `src/hooks/useNetworkSeries.ts`**：按 `snapshot` 的**对象身份**触发，
停采时不会重跑。

**改 `src/components/tabs/NetworkTab.tsx`**：接口表（行可点选、选中行高亮）
+ **接口详情**（状态 / IPv4 / IPv6 / MAC / 当前速率 / 窗口峰值 / 窗口均值 /
累计收发 / 采样点数 / 曲线口径说明）+ **两条 per-interface 曲线**（下行 / 上行，复用既有 `TrendChart`）。
- 选中的接口消失时（网卡被拔、容器退掉）自动落到还存在的那个上，
  否则详情区会一直显示一个已不存在的接口的旧数据。

**改 `src/App.tsx`**：接上 `useNetworkSeries(snapshot)` 并把 `series` 传给 `NetworkTab`。

## 7. 交互契约轮（2026-10-26）

依据 `z-biz-tool-lead/008_组织规范/004_产品交互契约.md` 逐条对照。本轮**只动前端**，Rust 未改。

### 7.1 动作真实性 / 错误不吞

- `useProcessStream`：订阅失败、启动失败、取列表失败、停止失败、查询失败不再只落控制台——前四类写进
  `error` 状态，进程页顶部用 `Alert` 报「进程流没有建立」并说明下方表格可能一直为空、切页签会重试；
  停止/查询失败仍 `console.warn` 并保留原文，不当成功。
- `useSystemMonitor`：静态系统信息读取失败进 `staticError`，系统信息页改为警示态，
  明说「实时采集与其它页面不受影响，不会用默认值顶替」，不再永远停在「正在读取…」。
- `scanJunk` 的进度订阅失败降级为「扫描照常，界面只少进度条」的明确日志，不静默。

### 7.2 视图三态

- 进程页：未连上（错误 Alert）≠ 正在建立（info Alert）≠ 连上但为空（表格自己的空态）。
- 大文件页：`未扫描` 显示「点击“扫描”开始查找大文件」，`扫描完成且 0 命中` 显示
  「主目录之下没有大于 N MB 的文件」；扫描中禁用按钮。
- 系统信息页：读不到（warning）≠ 读取中（info），两者文案不同。

### 7.3 破坏性操作

- 结束进程、清理选中项、批量结束、启动项禁用/删除/恢复四个确认框：危险按钮 `danger`、
  明确后果与对象名，**默认焦点落在“取消”**。
  实现用 `cancelButtonProps.ref` + `afterOpenChange` 聚焦——`<Modal>` 组件的 `focusable`
  只有 `trap/focusTriggerAfterClose`，`focusable.autoFocusButton` 属于静态 `modal.confirm`，不能照搬。
- 清理确认框继续列出真实落点目录；启动项仍要求输入名称二次确认。

### 7.4 键盘与可访问名

- 告警历史的图标刷新按钮补 `aria-label="重新读取告警历史"`（Tooltip 不替代可访问名）。
- 顶栏窄窗只留图标的按钮（告警阈值/迷你模式/暂停/刷新 DNS）都带 `aria-label` 与 Tooltip。

### 7.5 900×600 与双主题

- 顶栏原来在 900 宽下折成 3 行、高 **233 px**，标题与控件被挤压；改为窄窗隐藏按钮文字、
  主机名隐藏、间距收紧后回到 **81 px 单行**，`header.scrollWidth == clientWidth == 900`，
  `documentElement.scrollWidth == 900`。
- 卡片头在窄窗允许换行（标题与 extra 各占一行），不再把标题挤成截断。
- **修掉一个真 bug**：`index.css` 里的 `[data-theme="dark"]` 规则此前没有任何 JS 写入该属性 ⇒
  深色算法只作用于 antd 组件，`body` 与 `.monitor-card` 仍是浅色。现在 `App` 在 `darkMode`
  变化时写 `documentElement.dataset.theme`，深色下 body 为 `#141414`。
